FoodResQ architecture

Web: React + TypeScript + Vite. API: Express + TypeScript, MongoDB, Socket.IO. AI: FastAPI optional OpenAI listing assistant. Maps: Leaflet/OpenStreetMap; OSRM multi-stop routing integration is a follow-up. Media: Cloudinary signed uploads to be configured.

Matching defaults: distance 30%, quantity fit 25%, urgency 20%, category 15%, receiver capacity 10%. Eligibility gates require verified receiver, category compatibility, capacity and storage compatibility. Results include explanations.

Concurrency: conditional MongoDB findOneAndUpdate reserves available, unexpired donations; unique donation/receiver request index prevents duplicates. Production multi-document flows should use replica-set transactions.

Safety: AI cannot certify food safety, freshness, contamination or allergens. Handling notes are donor-provided. Route durations are estimates, not guarantees. Environmental impact must disclose assumptions.
